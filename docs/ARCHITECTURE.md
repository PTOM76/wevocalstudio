# アーキテクチャ設計
WeVocal Studio は、複数のトラックに波形ブロックを並べて編集する DAW。仕組みは WeVocalSynth にそろえる。Synth と Analyzer にある機能は Studio にもそろえる。React の画面と、Web Audio の再生、書き出しで構成する。プロジェクトの状態と履歴は React の外の文書（`ProjectDocument`）が持ち、画面は React のフックで読む。

関連: [コーディング規約](CODING.md) / [バージョン履歴](VERSION.md) / [アルゴリズム](ALGORITHM.md)

## 設計の方針
WeVocalSynth（docs/ARCHITECTURE.md）と同じ。

| 方針 | 具体的には |
| --- | --- |
| 1 つの変更は 1〜2 か所で済ませる | 同じ定義を 2 か所に書かない |
| 一緒に変わるものは一緒に置く | フォルダーは同じ種類が 2 つ以上そろってから作る |
| 音声の計算は画面を知らない | `project.ts`、`engine.ts` は React に触れない |
| 保存したデータは壊さない | 設定のキー、保存の形を変えるなら古い形を読み替える |
| 失敗は黙らない | 利用者の操作の失敗は、通知か画面で理由を見せる |

## 原音から作る
Synth は編集した音声を書き換えて持つ。Studio は元の音（`Source`）を書き換えず、波形ブロックの値（位置、元の音の範囲、音量、ピッチ、フェード）から、再生と書き出しのたびに音を作る（非破壊の編集）。

- ピッチなどの重い処理で毎回作るのが遅いときだけ、例外としてキャッシュを持つ。キャッシュは消しても作り直せるものにする
- ピッチの処理方式は Synth と同じものを使う。処理は wevocal-lib（Rust の `pipeline.rs` など）にあり、`dsp/` はそれを wasm で公開するだけ。Synth から使う処理は wevocal-lib に移してから使う
- ピッチなどは、元の音を 4 秒ごとのかたまり（前後 0.5 秒の余白つき）に分けて作り、設定とかたまりの番号でキャッシュする（`src/dsp/pitch.ts`）。区切りは元の音の時刻なので、範囲の違う波形ブロックどうしでも同じかたまりを使い回す。使われなくなったかたまりも 300MB まで残す（戻したときに作り直さない）
- 再生位置（止まっていれば編集カーソル）に近いかたまりから作る（鳴らない波形ブロック、つまりミュートしたものや鳴らないトラックのものは、鳴るものを全部作ってから）。できたかたまりから鳴らす。つなぎ目は 5ms で重ねる。できていない所は鳴らさない
- Worker は CPU のコアの数に合わせて 2〜4 つ使う。wasm は進み具合を返し（WeVocalSynth と同じ report_progress）、ステータスバーのゲージと波形ブロックの「処理中 n%」に出す
- wasm は SIMD（simd128）を入れてビルドする（WeVocalSynth と同じ `dsp/.cargo/config.toml`）
- 波形ブロックの音は、トラックごとのミキサー（AudioWorklet）が今かかっている所だけを読んで足す。再生中に変えたら声の一覧を送り直し（変わった声は 20ms でつなぐ）、トラックとマスターは値だけを変える（`engine.ts` の Graph、`src/mixer/`、[アルゴリズム](ALGORITHM.md)）

## 画面を軽くする
DAW と同じく、毎フレーム変わるもの（再生位置）と、変えたときだけ変わるもの（波形ブロック）を分けて描く（WeVocalSynth と同じ）。

- 再生位置は React の状態に入れない。カーソルの線（上に重ねた canvas）、時間の表示、ミニマップが、再生中だけ毎フレーム自分で読む
- 時間軸の本体（波形ブロック、グリッド）は、プロジェクトや表示範囲が変わったときだけ描き直す
- 波形は元の音ごとに、何段階かの細かさのピーク（最小と最大）を一度だけ作って使う（`src/peaks.ts`）

## 文書と履歴（`src/document/`）
デスクトップの編集ソフトと同じく、データ、変更、画面を分ける。依存は一方向（画面 → 文書）で、文書は画面も音声も知らない。

| 置き場所 | 持つもの |
| --- | --- |
| `ProjectDocument.ts` | プロジェクトと選択（波形ブロック、トラック、範囲）を履歴のストア（wevocal-lib の `createHistoryStore`）に持つ。変更は `change(関数, merge, 選択)` で通す。`merge` が同じ続けての変更（ドラッグ、スライダー）は 1 段にまとまり、`cancelMerge` で取り消せる（ドラッグ中の Esc）。フリーズ中のトラックの保護は `guard` で渡す |
| `edits/blocks.ts`、`tracks.ts`、`project.ts` | プロジェクトを受け取って新しいプロジェクトを返す純粋な関数（ブロック、トラック、マーカー、テンポ、マスターの変更）。React を使わないのでテストで試せる |
| `useProject.ts` | 文書を 1 つ作り、画面から使う形（コールバック）にして渡すだけ |

- 選択も履歴の 1 段になり、元に戻せる。カーソルと表示の位置は入れない
- プロジェクトの変更は、`edits/` の関数を `change` に渡す形で書く。画面のコードにプロジェクトを組み替える処理を書かない
- MIDI ブロックの有無は `midiBlocks(p)` で読む（`p.midi ?? []` を書かない）
- テストは `npm test`。文書と `edits/` に付ける

## 画面と操作の置き場所
| 置き場所 | 持つもの |
| --- | --- |
| `App.tsx` | 画面の組み立てだけ。状態と操作は下のフックに置く |
| `useTransport.ts` | 再生、編集カーソル、再生カーソル、一時停止、繰り返しと、再生、一時停止、停止、移動の操作 |
| `useActions.ts`、`commands/` | 操作の静的な表（`table.ts` の COMMANDS。型と判定、実行の仕組みは PevenMUI の commands で、Synth と共通）、メニューバーと右クリックのメニュー（`menus.ts`）、型（`types.ts`）。今の選択と設定（CommandEnv）は、実行と判定のときに渡す。キーの割り当てとメニューは操作の名前で呼ぶ |
| `DocContext.tsx` | 文書を部品に渡す。時間軸、解析の欄、ダイアログ、コマンドは props ではなくここから選択、範囲、プロジェクトの変更を使う |
| `Timeline.tsx`、`timeline/` | 時間軸の画面（`Timeline.tsx`）、描画（`useTimelineDraw`）、ホイール、トラックの欄（`TrackColumn`）、操作（`useTimelinePointer`。ドラッグの種類ごとの状態を持つ）、ドラッグの計算（`dragMath`。純粋な関数）、ダブルクリックとメニューの振り分け（`menuHandlers`） |
| `pianoRoll/` | ピアノロール。表示の位置（`useRollView`）、ドラッグの計算（`gesture`。純粋な関数）、編集（`useRollEdit`）、描画（`draw`） |
| `engine.ts`、`engine/` | 再生と書き出し。音のグラフ（`graph`）、再生（`player`）、書き出しの描画（`render`）、共通の補助（`params`）、音符の並べ替え（`midiEvents`。純粋な関数） |

- ファイルは 500 行以下にする。超えそうなら、状態を持つ部分（フック）と、計算だけの部分（純粋な関数。テストを付ける）に分ける
- 画面のコードは、プロジェクトを組み替える処理を直接書かず、`document/edits/` の関数を文書に渡す

## データの形（`src/project.ts`）

| 型 | 持つもの |
| --- | --- |
| `Source` | 読み込んだ音声（`Clip`）、名前、長さ |
| `Master` | 音量、パン、ミュート（全トラックを混ぜたあとに掛ける） |
| `Track` | 名前、音量、パン、ミュート、ソロ、親のトラック（サブトラック。子は親のすぐ後ろに並べる）、フリーズ（書き出した音の元の音と位置。あれば波形ブロックの代わりに鳴らし、その波形ブロックは変えない。`src/freeze.ts`） |
| `Block`（波形ブロック） | トラック、元の音、時間軸の位置、元の音の開始位置、長さ、音量、ピッチ、ピッチの処理方式、フォルマントを保つか、フェード、ミュート |

## 保存
| 対象 | 保存先 | 形式 |
| --- | --- | --- |
| プロジェクト | ダウンロード（.wvst） | "WVST"＋ヘッダ JSON＋元の音の f32（`src/projectFile.ts`） |
| 自動保存 | IndexedDB（`wevocalstudio` / `kv` / `autosave:meta`、`autosave:source:<id>`） | 元の音は書き換えないので 1 回だけ書き、メタ（トラック、波形ブロック）は 0.5 秒待って書く。書き込みと読み出しは Worker で、元の音は 4 MB ずつ空いている間に渡す。指定フォルダーへの写しは別の列で行い、復元読み込みを待たせない（`src/storage/`） |
| 設定 | localStorage（`wevocalstudio.settings`） | JSON |

## 登録する表
| 足すもの | 登録する場所 |
| --- | --- |
| キーの割り当て | `src/keymap.ts` の DEFAULT_KEYS（操作の名前 → 既定のキー）と、`useActions.ts` の commands。名前は訳文の `menu.<操作の名前>`。設定で変えた分は `settings.keys` |
| 訳文 | `npm run i18n -- add`（`src/lang/` の全言語に同じ位置で足す） |

## 共通の部品
| 置き場所 | 中身 |
| --- | --- |
| PevenMUI | 画面の部品（メニュー、設定、ダイアログ、ステータスバー） |
| wevocal-lib | 音声の読み込みと書き出し、Synth と共通の処理（ピッチ、伸縮、EQ、録音、ミニマップ）。WeVocal プラグイン（FX の列。型は plugin-sdk/、ホストは web/src/plugins/。設計は memo/effects.md） |
| WeVocalAnalyzer の src/ | スペクトログラム、F0 などの解析（本体に入れる。AI のモデルを使う歌詞の文字化だけは追加機能にする予定） |

どちらも隣の WeVocalSynth の中のものを先に使い（`vite.config.ts`、`tsconfig.json`）、なければ自分の submodule を使う。

## 技術選定
| 項目 | 選定 | 理由 |
| --- | --- | --- |
| 画面 | React + TypeScript + MUI（PevenMUI） | Synth と同じ部品を使う |
| 提供 | PWA。ネイティブ版は Tauri を第一候補 | VST プラグインはブラウザでは読み込めない。Electron は容量と速さの点で避ける |
