# アーキテクチャ設計
WeVocal Studio は、複数のトラックに波形ブロックを並べて編集する DAW。仕組みは WeVocalSynth にそろえる。Synth と Analyzer にある機能は Studio にもそろえる。React の画面と、Web Audio の再生、書き出しで構成する。状態管理は React のフックだけで行う。

関連: [コーディング規約](CODING.md) / [バージョン履歴](VERSION.md)

## 設計の方針
WeVocalSynth（docs/ARCHITECTURE.md）と同じ。

| 方針 | 具体的には |
| --- | --- |
| 1 つの変更は 1〜2 か所で済ませる | 同じ定義を 2 か所に書かない |
| 一緒に変わるものは一緒に置く | フォルダーは同じ種類が 2 つ以上そろってから作る |
| 音声の計算は画面を知らない | `project.ts`、`engine.ts` は React に触れない |
| 保存したデータは壊さない | 設定のキー、保存の形を変えるなら古い形を読み替える |
| 失敗は黙らない | 利用者の操作の失敗は、通知か画面で理由を見せる |

## 原音から作る
Synth は編集した音声を書き換えて持つ。Studio は元の音（`Source`）を書き換えず、波形ブロックの値（位置、元の音の範囲、音量、ピッチ、フェード）から、再生と書き出しのたびに音を作る（非破壊の編集）。

- ピッチなどの重い処理で毎回作るのが遅いときだけ、例外としてキャッシュを持つ。キャッシュは消しても作り直せるものにする
- ピッチの処理方式は Synth と同じものを使う。処理は wevocal-lib（Rust の `pipeline.rs` など）にあり、`dsp/` はそれを wasm で公開するだけ。Synth から使う処理は wevocal-lib に移してから使う
- ピッチなどは、元の音を 4 秒ごとのかたまり（前後 0.5 秒の余白つき）に分けて作り、設定とかたまりの番号でキャッシュする（`src/dsp/pitch.ts`）。区切りは元の音の時刻なので、範囲の違う波形ブロックどうしでも同じかたまりを使い回す。使われなくなったかたまりも 300MB まで残す（戻したときに作り直さない）
- 再生位置（止まっていれば編集カーソル）に近いかたまりから作り、できたかたまりから鳴らす。つなぎ目は 5ms で重ねる。できていない所は鳴らさない
- Worker は CPU のコアの数に合わせて 2〜4 つ使う。wasm は進み具合を返し（WeVocalSynth と同じ report_progress）、ステータスバーのゲージと波形ブロックの「処理中 n%」に出す
- wasm は SIMD（simd128）を入れてビルドする（WeVocalSynth と同じ `dsp/.cargo/config.toml`）
- 再生中に変えたら、変わった波形ブロックだけを差し替え（20ms でつなぐ）、トラックとマスターは値だけを変える（`engine.ts` の Graph）

## 画面を軽くする
DAW と同じく、毎フレーム変わるもの（再生位置）と、変えたときだけ変わるもの（波形ブロック）を分けて描く（WeVocalSynth と同じ）。

- 再生位置は React の状態に入れない。カーソルの線（上に重ねた canvas）、時間の表示、ミニマップが、再生中だけ毎フレーム自分で読む
- 時間軸の本体（波形ブロック、グリッド）は、プロジェクトや表示範囲が変わったときだけ描き直す
- 波形は元の音ごとに、何段階かの細かさのピーク（最小と最大）を一度だけ作って使う（`src/peaks.ts`）

## データの形（`src/project.ts`）

| 型 | 持つもの |
| --- | --- |
| `Source` | 読み込んだ音声（`Clip`）、名前、長さ |
| `Master` | 音量、パン、ミュート（全トラックを混ぜたあとに掛ける） |
| `Track` | 名前、音量、パン、ミュート、ソロ、親のトラック（サブトラック。子は親のすぐ後ろに並べる） |
| `Block`（波形ブロック） | トラック、元の音、時間軸の位置、元の音の開始位置、長さ、音量、ピッチ、ピッチの処理方式、フォルマントを保つか、フェード、ミュート |

## 保存
| 対象 | 保存先 | 形式 |
| --- | --- | --- |
| プロジェクト | ダウンロード（.wvstudio） | "WVST"＋ヘッダ JSON＋元の音の f32（`src/projectFile.ts`） |
| 自動保存 | IndexedDB（`wevocalstudio` / `kv` / `autosave:meta`、`autosave:source:<id>`） | 元の音は書き換えないので 1 回だけ書き、メタ（トラック、波形ブロック）は 0.5 秒待って書く。書き込みと読み出しは Worker で、元の音は 4 MB ずつ空いている間に渡す（`src/storage/`） |
| 設定 | localStorage（`wevocalstudio.settings`） | JSON |

## 登録する表
| 足すもの | 登録する場所 |
| --- | --- |
| キーの割り当て | `src/keymap.ts` の DEFAULT_KEYS（操作の名前 → 既定のキー）と、`useActions.ts` の commands。名前は訳文の `menu.<操作の名前>`。設定で変えた分は `settings.keys` |
| 訳文 | `npm run i18n -- add`（`src/lang/` の全言語に同じ位置で足す） |

## 共通の部品
| 置き場所 | 中身 |
| --- | --- |
| PevenMUI | 画面の部品（メニュー、設定、ダイアログ、ステータスバー） |
| wevocal-lib | 音声の読み込みと書き出し、Synth と共通の処理（ピッチ、伸縮、EQ、録音、ミニマップ） |
| WeVocalAnalyzer の src/ | スペクトログラム、F0 などの解析（本体に入れる。AI のモデルを使う歌詞の文字化だけは追加機能にする予定） |

どちらも隣の WeVocalSynth の中のものを先に使い（`vite.config.ts`、`tsconfig.json`）、なければ自分の submodule を使う。

## 技術選定
| 項目 | 選定 | 理由 |
| --- | --- | --- |
| 画面 | React + TypeScript + MUI（PevenMUI） | Synth と同じ部品を使う |
| 提供 | PWA。ネイティブ版は Tauri を第一候補 | VST プラグインはブラウザでは読み込めない。Electron は容量と速さの点で避ける |
