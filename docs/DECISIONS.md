# 決定事項
実装していて問題を踏み、その結果として決まったもの。知らずに触ると同じ問題を踏むので、新しいコードでも同じようにする。音声処理（ピッチ、伸縮）の決定事項は WeVocalSynth の docs/DECISIONS.md にある。

設計全体の方針は [アーキテクチャ](ARCHITECTURE.md)、書き方の決まりは [コーディング規約](CODING.md) を参照。

## 再生

### 波形ブロックの音は、トラックごとの AudioWorklet のミキサーで足す
最初は波形ブロックの片ごとに AudioBufferSourceNode を作り、時刻を指定して予約していた。予約したノードは数が多いほど重くなり、再生位置を変えるたびに全部作り直す。波形ブロックが 907 個の曲で再生位置を何度も変えると、数秒鳴らなくなった。

そのため、トラックごとのミキサー（AudioWorklet）が 128 サンプルごとに今かかっている声だけを読んで足す形にした。再生位置を変えても読む位置が変わるだけで、ノードは作らない（[アルゴリズム](ALGORITHM.md)）。

### 書き出しも再生と同じミキサーで描く
再生と書き出しで別の仕組みにすると、同じプロジェクトでも音が変わる。書き出しは OfflineAudioContext で同じミキサーを動かす。送った音をミキサーが受け取ったのを確かめてから（ping と pong）描き始める。

### ピッチを変えた音は先に作ってキャッシュし、それまでは下見の音を鳴らす
リアルタイムのピッチ変更は遅れがあり、長さも正確でない。かたまりを Worker で先に作り、ミキサーはできたものを読むだけにした。間に合わない所を無音にしないよう、再生位置から 15 秒先までは SOLA の下見を先に作って鳴らし、高品質のものができたら 20ms で差し替える。

ピッチを変えたときに元の音が一瞬鳴る、続けて変えると固まる、鳴らし直しでぶつっと鳴る、の 3 つもこの順番で防いでいる。ドラッグ中の鳴らし直しとミニマップの作り直しは後に回す。

### 再生中に変えた声は 20ms でつなぐ
声の一覧が届いたら、key で前の声と比べ、sig（値を比べる文字）が同じならそのまま鳴らし続ける。変わった声だけを 20ms でフェードアウトし、新しい声をフェードインする。全部を鳴らし直すと、再生中に波形ブロックを動かすたびにぶつっと鳴る。

### オフラインで描いたグラフは、描き終わったら破棄する
先読み（`anticipate.ts`）と書き出しで作ったグラフ（FX のプロセッサー、音源）を残していたため、再生を繰り返すと処理が増え続けて重くなった（2026-10-23）。描いたあとに `dispose` する（`engine.ts`）。

## 波形ブロック

### 元の音は書き換えず、波形ブロックの値から作る
Synth は編集した音声を書き換えて持つが、Studio は複数の波形ブロックが同じ元の音を参照し、あとから何度でも値を変える。書き換えると、分割や端の調整で元に戻せなくなる。確定（`bake.ts`）も、新しい元の音を足して置き換えるだけで、前の元の音は消さない。

### ピッチカーブとピッチのエンベロープは、元の音の時刻で持つ
時間軸の時刻で持つと、分割や端の調整、元の音の開始位置の変更でカーブがずれる。元の音の時刻なら、どう切っても同じ所に同じ値がある。

### 新しい波形ブロックと分割した切れ目には 10ms のフェードを付ける
切れ目で波形が急に途切れると、プツッという音が出る。

### 24 半音を超えるピッチは、何回かに分けて処理する
大きく上げる処理を 1 回で行うと、途中で音が長くなりすぎる。wasm が長さを変えずに 24 半音ずつに分けて処理する（±256 半音まで）。

## 保存

### 保存の形と設定のキーを変えるときは、古い形を読み替える
自動保存と .wvst は、利用者の手元に古い形のまま残る。読み込み時に既定値で埋め、古い項目は新しい項目に読み替える（[プロジェクトファイルの形式](PROJECT_FORMAT.md)）。IndexedDB を PevenMUI の `createIdb` に替えたときも、保存先の名前は変えず、保存済みのデータをそのまま読めるようにした。

### 自動保存の元の音は 1 回だけ書く
元の音は書き換えないので、変更のたびに書き直す必要がない。変わるのはメタ（トラック、波形ブロック）だけで、0.5 秒待ってから Worker で書く。

## 画面

### 再生位置は React の状態に入れない
毎フレーム変わる値を React の状態に入れると、画面全体が毎フレーム描き直される。カーソルの線、時間の表示、ミニマップが、再生中だけ毎フレーム自分で読む。

### 画面の部品は自作せず、Synth の部品を PevenMUI と wevocal-lib に移して使う
Synth と Studio で同じ役目の部品を別に作ると、見た目と動きがずれ、直すときも 2 か所になる。Synth に同じ部品があれば PevenMUI（音声は wevocal-lib）に移し、Synth もそれを使う形にしてから Studio で使う。置き方（レイアウト）は Studio 独自でよい。

### 空のときの案内に、メニューと同じ操作を並べない
形式、ファイルを選択、録音、最近使用したファイルを案内に並べていたが、どれもメニューからできるのでやめた。

## 設定

### Synth にある設定は、同じ名前でそろえる
Synth と Studio を行き来する利用者が迷わないよう、同じ意味の設定は同じ名前と同じ置き場所にする。名前が違っていたもの（`follow` → `followPlayhead` など）は、古い名前で保存した値を読み替えて引き継ぐ。

Studio に入れないと決めた設定（2026-10-23）: `historyMemoryMb`（Studio の履歴は元の音を写さない）、`fastMath`、`parallelProcess`、`spliceFadeMs`、`realtimeAlign`（Synth の処理方式にだけある）、`f0SilenceDb`、`f0Voicing`（Studio の F0 は analyzer の YIN）。
