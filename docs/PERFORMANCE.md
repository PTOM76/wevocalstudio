# 速さの改善
時間軸の描画、ピッチの処理、再生、自動保存について、直したところと、残っている候補を記録する。仕組みそのものは [機能の仕組み](INTERNALS.md) と [アルゴリズム](ALGORITHM.md) を参照。加工の処理方式そのものの速さは WeVocalSynth の docs/PERFORMANCE.md にある。

測ってから着手する（設定の「開発者向け」のデバッグ表示の数値と、ブラウザの Performance タブ）。

## 直したもの（2026-10-17）

| 場所 | 行ったこと | 理由 |
| --- | --- | --- |
| 時間軸の描画 | 波形ブロックのピッチの値（`paramsOf`）を Block ごとにキャッシュする | 描くたびにピッチカーブ全体（数千点）をハッシュしていた。Block は書き換えないので、同じオブジェクトなら同じ値 |
| 時間軸の描画 | 元の音とトラックを頭で Map にし、トラックの上端を累積の配列にする | 波形ブロックごとの `find` と、トラック数の 2 乗の計算をなくす |
| 時間軸の描画 | 重なりの段の割り当て（`layoutRows`）を、波形ブロックの配列が同じなら使い回す | 描くたびとドラッグのたびに全部を計算していた |
| 時間軸の描画 | 波形を 1 つのパスで塗る | 1 画素ずつ `fillRect` していた（幅 2000px なら 2000 回） |
| 再生のグラフ | 同期のときの `find` をなくし、同じ値をつまみに書き込まない | ドラッグ中は 50ms ごとに同期が走る |
| ミニマップ | 波形ブロックごとの小さな音を使い回し、合成だけをやり直す | どの変更でも全部を作り直していた |
| ピッチの処理 | Worker へ音を transfer で渡し、キャッシュの合計の大きさを持っておく | 受け渡しで写しが 2 回でき、毎回全部のかたまりの大きさを足していた |
| ミキサー | エンベロープの値を、前の位置から探す | 128 サンプルごとに、声ごとに頭から探していた |
| 先読み | 変わったかを比べる文字（`signature`）をキャッシュする | 250ms ごとに、波形ブロック全部を `JSON.stringify` していた |
| EQ（wevocal-lib） | 同じ値を書き込まない。オフの処理は止める | 書き込み続け、オフでも処理し続けていた |

## 残っている候補

| 場所 | 候補 |
| --- | --- |
| 時間軸の描画 | 波形ブロックの絵を OffscreenCanvas にキャッシュし、スクロールは `drawImage` だけにする。かたまりができたときの描き直しをまとめる |
| ピッチの処理 | ピッチに関係ない変更（音量、位置、選択）では、かたまりの一覧を組み直さない。下見のかたまりの余白を短くする |
| ミキサー | 前と同じ Block の声を使い回す。速度が 1 のときとモノラルのときの内側のループを分ける |
| 自動保存 | 変わっていなければ Worker に送らない。ピッチカーブを Float32Array で持つ |
| 読み込み | 波形のピークを、最初の描画で同期で作らず、読み込み後に作る |
| 画面 | デバッグ表示に `stall 168ms: render App` が表示される。React の Profiler で原因を見る |
